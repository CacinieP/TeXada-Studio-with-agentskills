# LaTeX 与 Markdown 清洗

直接编辑用户指定的源文件，让用户继续在 VS Code 查看差异和预览。本技能兼容能读取
`SKILL.md` 并操作本地文件的 coding agent；宿主负责调用技能，VS Code 负责编辑和预览。

## 选择范围和模式

- **检查**：用户要求诊断、审阅或只检查时，读取并报告，不修改。
- **清洗（默认）**：整理格式，保持内容含义。清晰且属于本次范围的修改直接完成；
  不确定的问题保留原文并记录，不必为每一项暂停。
- **修复**：用户要求修复错误时，结合定义、文件和日志做有依据的修复，再验证。
- **OCR 校订与对比**：用户要求清洗 OCR 并对照原稿时，先建立页码与片段对应，再恢复
  有原页证据的正文、公式、表格及阅读顺序。读 [OCR 校订](references/ocr.md)。
- 模板转换、OCR 纠错、润色和文献元数据补全，只有在本次请求包含这些工作时执行。

用户的明确指令优先于本技能的默认约定。按文件读取
[TeX 规则](references/tex.md) 或 [Markdown 规则](references/markdown.md)；混合项目按需读两者。
调用脚本前查看 [工具与 VS Code 使用说明](references/tools.md)。

## 执行流程

1. **识别项目**：确认目标文件及相关子文件、主文件、图片、文献库、预览方言和现有配置。
   优先沿用项目风格，不固定为两空格缩进。把完整文档和仅能嵌入的片段区分开。
2. **记录基线**：读取当前工作区差异，记录本次目标的当前内容。Git 仓库中的未提交修改
   也是基线的一部分；不要用 HEAD 代替它，也不要覆盖用户修改。手工编辑前在工作临时目录
   保存目标文件副本；脚本的 `--write` 会先建立逐字节备份。文件已变化时重新读取。
3. **诊断**：报告文件、行号、证据和影响。完整 TeX 项目若工具可用，先按项目配置编译；
   原稿编译失败仍可做有依据的修复。静态疑点、实际编译错误和审美建议分别描述。
4. **修改**：按问题类型做小范围修改，保护正文、数学表达式、代码、注释、链接和引用键。
   自动脚本仅作保守空白处理。需要更广的格式整理时，按项目配置使用格式化器或局部编辑，
   检查差异。不得用全文正则替代 TeX / Markdown 上下文判断。
   对照 OCR 原稿的内容修改记录原页、原片段及替换片段；重复的精确替换可用
   `apply_verified_edits.py`，它检查补丁位置与文件版本，不判断证据内容是否真实。
5. **验证**：查看全部修改差异。TeX 实际编译并读取最终日志；Markdown 在实际方言下检查
   段落、列表、代码、公式和链接，条件允许时在 VS Code 预览。新增脚本规则要覆盖保护区域、
   备份一致性及重复执行无新增变化。纯格式修改可额外比较 PDF 提取文本，但文本相同不证明
   数学或版式完全相同。
6. **交付**：简述已改文件、修改理由、已运行的验证及剩余问题。明确写出编译成功、失败、
   超时或未执行及其原因，不能把工具缺失当成成功。没有视觉检查时不要宣称版式验收通过。

## 共同约束

- 不因出现次数、外观接近而合并数学符号；不凭空补参考文献、图像或原文。
- 保留代码、原始资源、有效跨文件引用、作者注释和未解决的 TODO / FIXME。
  只有明确要求清除，或本次确实解决了所标记问题，才移除相应标记。
- 空行、缩进、行尾空格和 `%` 都可能承载语义，先识别所在语法区域。
- 资源转换必须先生成并验证目标文件；替换扩展名不会转换内容，PNG 装入 PDF 也不会变成矢量图。
- 不统一改写有效引用命令、文献键或链接锚点。需要重命名时追踪完整依赖并验证。
- 沿用用户当前的编辑器、编译器和预览流程；不要为一次清洗安装新工具或更改全局设置。
  缺工具时完成可做的静态检查，并说明验证缺口。用户已要求安装或配置时按其范围执行。

## 完成报告

用简短文字或表格列出：范围、已修复问题、验证证据、剩余事项。
对未解决事项给出具体位置和原因，不输出虚构的修复计数。只有检查模式才把可执行修改留作建议。
分别报告源码/补丁检查、实际编译或公式解析、内容核对、视觉检查；某项未运行就标明未运行。
批量任务区分处理文件数、实际改动数和已对照原页的范围；不能把抽查结果推广为全文准确率。
需要可复核交付时保留 before、after、统一 diff 和改动依据，按
[验证与对比](references/verification.md) 组织证据。技能维护者可用
[行为测试](tests/behavioral/CASES.md) 检查 agent 的实际执行结果。
处理一套 OCR 语料、合并已核实片段并导出逐本文本差异时，读
[批量 OCR](references/corpus.md)；其中包含可重放的 50 本 GTM 实例。

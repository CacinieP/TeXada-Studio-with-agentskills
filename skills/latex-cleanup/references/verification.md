# 验证与前后对比

按任务实际风险选择检查，不为小改动强制生成完整报告包。

| 层次 | 有效证据 | 不能推出的结论 |
|---|---|---|
| 文件与补丁 | before/after 哈希、精确 diff、备份、批准补丁重放一致 | 数学内容正确 |
| 语法与构建 | 真实编译退出码、最终日志；公式解析器版本与诊断 | 原意保持、排版美观 |
| 内容 | 对照原稿逐项核对或明确的内容不变量 | 未检查页面也正确 |
| 视觉 | 实际新预览/渲染的具体页面检查 | 未显示的公式和引用均正确 |

状态使用 `passed / failed / not_run / review` 等明确值；不把工具未安装或返回空结果记为成功。
采用模型分数时记录它的定义；生成分数、规则等级和模型自报 confidence 都不能直接当作
“修改正确的概率”。是否修改取决于当前任务范围与证据，不设置跨项目通用的 0.85 门槛。

## 可复核的批量交付

- `manifest.json`：每个输入的来源、范围、字节哈希与输出位置；资源搬移也写入。
- `before` / `after` / `changes.diff`：来源快照、结果与完整差异。
- 修改记录：说明机械格式修改与原稿校订各有哪些，尚待核对的内容独立列出。
- 验证结果：逐层列出实际执行、配置、产物和限制；报告由这些记录汇总。

哈希比较当前磁盘输入与开始时的快照，确认任务期间是否发生变化。相同内容的重新处理
应无额外格式改动。原页内容修复是一次性补丁；重跑旧补丁应因源哈希变化而拒绝，不能
将这种预期拒绝当成技能不幂等。

不按改动越多给更高分。正确保留、识别歧义、报告验证未完成都可能是正确行为。
技能的脚本回归和 agent 行为测试分别记录；单次 subagent 执行通过不等于跨模型触发率。

# 3 分钟无剪辑演示脚本（断网实机）

要求：单镜头不剪辑；包含一次**故意注入的错误**与自动修复全过程；左上角常驻终端 `htop`/内存监控。

## 0:00–0:20 问题引入

- 展示一份扫描版试卷页：「今天要把这页 PDF 变成可检索的结构化数据」
- 一句话：现有工具只做提取，错误会顺流而下；我们做的是**质检 + 修复 + 证据链**

## 0:20–1:00 全流程跑通（正常样本）

- `python -m docforensics run samples/paper-01/`
- 终端滚动展示：doc-layout-parse 结构树 → 两个质检 Skill 逐节点判定 → doc-report 生成
- 打开报告：全部 OK 节点 + 置信度

## 1:00–2:10 错误注入与自动修复（核心 70 秒）

1. 样本中预置两个错误：一个被 OCR 打错的公式（`\frac{1}{2}` 被识别成 `\frac{1}{3}`）、一张跨页断表
2. `doc-formula-verify`：SymPy 回判失败 → 终端打出 `RETRY` → 自动以 20% padding 重裁剪、
   提高分辨率调 VLM 重识别 → 二次回判通过 → 修复 + 留下原始 crop 证据
3. `doc-table-audit`：行列数与合计值交叉验算失败 → 标记跨页续表 → 拼接后复验通过
4. 打开报告 diff 视图：**每一处修改都能点开原始截图对照**

## 2:10–2:40 断点续跑

- 演示中途 `kill -9` 掉进程 → 重新运行 → 终端显示「跳过 N 个已完成节点，从断点继续」
- 一句话：长流程不怕中断，state.jsonl 记录每一步

## 2:40–3:00 收尾（为什么是这台机器）

- 内存监控展示 qwen3.8-27B 仅 16GB 常驻，**余下 ~100GB 全部是并发 KV 预算**
- 一句话：**这台机器跑的是十几路并发文档流质检，24GB 消费卡只能单流**；加上 SymPy 符号仲裁
  （刚才它拦下了 VLM 的幻觉修复），全程断网，数据不出本机

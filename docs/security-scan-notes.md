## Gitleaks 覆盖与例外

使用 Gitleaks 8.30.1，开启 `--redact=100`，先移除旧例外再核对三层扫描的实际覆盖。

| 范围 | 覆盖量 | 未应用例外的命中 |
| --- | --- | ---: |
| 全部可达 Git 历史 | 45个提交，约14.93 MB补丁文本 | 2 |
| 当时工作目录 | 约15.51 MB文件内容 | 2 |
| 全历史文件对象快照 | 464个唯一 blob，16,502,949字节 | 2 |

三层均命中 Monaco 上游的同两处压缩代码：`editor.main.js:631` 与 `tsWorker.js:320`。复核为 token / KeybindingResolver 表达式；104个 vendored 文件的 SHA256 均与固定包清单一致，保留上游原始字节和 MIT 许可。

`.gitleaksignore` 仅保留这两处对应的四条精确 fingerprint，分别用于 Git 历史和目录扫描。应用后，两类扫描均无未处理命中。更新 Monaco 或重写历史时需重新核对 fingerprint；原始脱敏报告和复核日志私密保存。

## 发布时如何使用这些结果

这些记录说明当时检查的范围与处理结果。发布新版本时重扫源码和 refs，并人工检查新增附件的内容、元数据及画面；许可和来源按发布清单另行复核。

历史重写更新可达引用，平台缓存、不可达对象、fork、旧 clone 和下载包需要分别处理。[GitHub 清理流程](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)说明平台侧处理方式；已暴露的凭据需撤销或轮换。协作者重新 clone，发布包从清理后的提交重建，避免旧对象回流。

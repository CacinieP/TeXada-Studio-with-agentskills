# TeXada Studio 本地版验收记录

日期：2026-11-02，Asia/Shanghai。基于 `main@9cb4133` 的 `feat/texada-studio-complete` 功能分支。本轮交付是单用户本地浏览器工作台，没有发布正式 Release。

## 交付范围

以 TeXWizard 的静态 UI 原型为设计来源，接入真实的本地编辑、文件管理、MiniCPM 识别、公式与表格检查、候选审阅及 PDF 交付。TeXWizard 原型本身没有识别后端，原型中的按钮在本轮替换为实际操作。

- 文档新建、导入、保存、刷新恢复、重命名及可恢复删除；保存使用内容版本检查。
- 本地 Monaco、未保存提示、快捷保存、主题、面板调节及窄屏审阅抽屉。
- 图片和 PDF 通过本机模型转写，单次 1–5 页；识别结果经审阅后新建文档，不覆盖原件。
- 行内、显示及常见数学环境的上下文抽取；跳过注释、原样区域及宏定义。复杂对齐或未知宏保留人工核对。
- 有界公式修复、确定性表格重算、Diff 与人工采用/拒绝；任务及审阅决定落盘，可恢复待审候选。
- 当前内容绑定的 PDF、多页预览、页码切换及导出；编辑或拒绝候选后旧 PDF 失效。
- 仅回环模型服务、绕过代理、拒绝重定向、不传云凭据；检查连接不保存草稿设置。
- 双击启动、同实例重新打开、依赖检查、已有模型复用及自有模型退出清理。

## 实际浏览器流程

真实 Chrome 共 10 项流程检查通过，页面错误及控制台错误均为 0：

1. 应用与随包 Monaco 加载。
2. 新建文档、编辑、保存、刷新后读取相同内容。
3. 两页文档真实编译、上一页/下一页、完整 PDF 下载。
4. 桌面界面截图。
5. 手工编辑后禁用旧 PDF，清除旧版本绑定。
6. 表格合计 `10 + 20` 从 `99` 生成 `30` 候选；模型调用为 0；拒绝后保留原文并记录决定。
7. 刷新页面，从本机历史恢复待审候选。
8. 采用候选、显式保存、刷新后保持修复结果。
9. 390px 窄屏无水平溢出。
10. 窄屏打开检查抽屉并拒绝候选，原文保持不变。

额外回归修复了：PDF 请求返回时文件名错配、重命名期间新增编辑被覆盖、采用后保存按钮未恢复，以及检查连接意外保存草稿设置。

## 实际本地模型与编译

以下 7 项 API smoke 最终全部通过，模型请求仅发送到本机回环服务：

| 测试 | 核对结果 |
| --- | --- |
| 模型连接 | 实际模型列表含所配置 4.7 1B 别名 |
| 离线两页编译 | 英文 article 生成 2 页 PDF |
| PDF 与 PNG | 下载文件分别具有有效 PDF、PNG 文件头 |
| 图片识别 | 一张固定合成页面返回待审候选，包含 `x^2+1` 锚点 |
| 两页 PDF 识别 | 返回两个来源页的转写与来源记录，未声称处理其他页 |
| 识别候选编译 | 识别结果包装为可编辑 LaTeX 后实际编译通过 |
| 公式修复 | `\frac{1}{2` 经一次实际模型调用返回 `\frac{1}{2}`，检查通过、无剩余问题 |

TeX 首次验收发现缓存缺失，并发现 macOS 默认字体集合可能要求不存在的 `STFangsong`。本轮显式预备了中文及英文常用资源；新文档和 OCR 候选使用 Fandol 字体预设。包含中文、标题、粗斜体、数学、表格和多页的固定样本已在只使用本地缓存的模式下重新编译通过。其他文档使用的新宏包仍可能需要显式预备。

## 结果边界

本轮证明本地工作流可以运行、保留版本与审阅证据并交付文档。它不是独立的 OCR 或数学准确率研究。

两页 PDF 的转写中，第二页的 `y = 2x + 3` 被输出为普通文本，未保持数学定界符；页码也被识别为正文。候选仍可编译，因此“编译通过”不能当作完整转写忠实度。界面保留人工审阅，不自动覆盖原文。未完成真实论文、手写、复杂版面、跨机器或 Windows/Linux 实机评测。

当前单位是单个 `.tex`，不包含整项目依赖上传、多人服务、任意 TeX 执行隔离或完整数学证明。后续独立评估与多文件能力见[路线图](roadmap.md)。

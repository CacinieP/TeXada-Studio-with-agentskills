## 项目概要

TeXada 是一个可运行的 LaTeX 质检与修复原型。使用者在浏览器中编辑源码、检查部分公式语法和简单表格合计，查看本地模型或规则生成的候选，再确认采用并导出文档及质检记录。项目关注修复过程的可审阅性，避免把成功编译或可解析的表达式当成内容正确的证明。

面向教师、科研写作者和文档整理人员，当前处理入口为单个 `.tex` 文件。独立 CLI 可以处理已有 `layout.json` 结构树，记录节点状态并支持同一输入的断点续跑。自动 PDF/OCR 提取、复杂表格结构重建和通用自主规划 Agent 尚未实现。

## 问题与使用场景

文档错误有不同层次。本次 LaTeX 案例中的分式缺少配对定界符，编译失败；模型补上结束命令后，使用者仍需核对公式是否保留原意。另一个案例把从0到1的 x 积分写成1，语法解析和编译都通过，但正确值为二分之一。早前报表合计115→105与缺失下标案例继续作为历史材料；它们说明的边界不能统一写成“修复成功”。

TeXada 分别展示规则检查、公式解析、编译结果和候选 diff。它保留原文，让使用者在看到依据后决定是否采用。当前支持范围较窄，适合演示和可信文档实验，不作为财务审计或数学证明工具。

## 已实现能力与范围

| 模块 | 已实现 | 边界 |

## 架构与 Agent Skills

Studio 的执行链为：浏览器与 Monaco → FastAPI → 公式及表格检查 → 必要时请求节点内模型 → 候选回判 → Tectonic 编译 → 人工审阅 → 导出。

CLI 的执行链为：已有布局树 → 按节点类型分发工具 → 至多两次修复尝试 → OK 或 NEEDS_HUMAN → 事件文件与报告。模型只负责提出候选，计算和状态处理由程序执行。

`SKILL.md` 封装使用时机、输入、步骤和限制，脚本承担确定性操作。`doc-formula-verify` 对应公式检查，`doc-table-audit` 对应表格检查，`doc-report` 约定输出记录。`doc-layout-parse` 当前是输入准备说明，未实现图像解析。`latex-cleanup` 提供独立的清理与验证工具；Studio 直接调用 Tectonic，没有调用该 Skill 的完整工具链。`spark-ops` 是操作者使用的部署约定。系统不使用 MCP。公式提供方现在真实读取并校验 Skill 正文，将其作为系统指令；文档公式作为独立用户数据。CLI/Studio 默认开启，off 模式用于同模型对照。Python 仍负责固定编排、调用预算与回判，模型没有自主调用工具的权限。[Agent Skills 规范](https://agentskills.io/specification)

六个 Skill 的执行入口、输入输出协议、错误路径及实际对照方法见 [Skills 技术报告](skills-technical-report.md)。它与面向操作的 [案例手册](casebook.md) 分工，避免把设计方案写成实测能力。

## 关键设计

公式检查器崩溃、异常输出或超时现在进入 NEEDS_ENV，保留原文并阻止不必要的模型调用；CLI 表格检查器故障则记录为 NEEDS_HUMAN / checker_error。公式增加完整解析检查，同时兼容合法的 left 与 right 尺寸命令。此检查仍受 SymPy 语法覆盖范围限制。[SymPy 解析文档](https://docs.sympy.org/latest/modules/parsing.html)

Monaco 0.52.2 的编辑器资源固定在仓库，由本站提供，保留 MIT 许可与摘要。界面补齐隐藏和折叠样式、diff 模型销毁、文档切换后的异步结果校验，以及任务异常后的按钮恢复。候选先进入对比视图，采用后写入编辑器。导出的 Markdown 质检报告含行号、修改前后内容、内容哈希、编译状态、模型标签和耗时。[Monaco 上游仓库](https://github.com/microsoft/monaco-editor)

原文与上传文档分离保存，上传内容写入被 Git 忽略的状态目录。启动必须显式设置非空认证密钥。部署遵守用户级安装方式，保留原有模型服务。

早前案例补充建立27个确定性输入，并将 Studio 文档扩至5份；本轮再增加8份原创 LaTeX 教学文档，当前共13份。新增案例覆盖定界符、分式、上下标、积分、正常对照、数学语义、多行抽取和引用边界，逐式契约见[案例清单](../samples/studio-cases.json)。原27例继续覆盖非法输入、不支持格式与大整数精度，未将新文档混入其计数。检查器输入崩溃、无数字合计虚报修改、Decimal 默认精度以及回判失败后继续模型尝试的问题已修复。CLI 新事件保存表格前后网格，报告展示真实差异。具体结果与未测范围见 [验证记录](validation.md)。

此前加入的事件协议将原检查、每次请求、候选回判与拒绝原因串联起来；模型字段区分配置标签和实际调用，纯规则任务明确0次请求。CLI 用输入及执行上下文摘要决定复用，避免同名节点换了内容还跳过。Studio 将前后编译产物按任务分开，历史预览不会被同名新任务覆盖。

三组评测从 Active Calculus 第二版的固定源码取6条公式并加入6条明确注入错误，数据单独采用 CC-BY-SA-4.0。[来源和复现](../samples/research/ACTIVE_CALCULUS_NOTICE.md) · [先导实验解读](skills-pilot-analysis.md)。这是一项小规模指令干预实验，不是自然 OCR 错误或已完成人工标注的独立基准。

## 复现方法

取得仓库后，按 README 创建 Python 虚拟环境并安装 `harness/requirements.txt`。在仓库根目录执行以下无需 GPU 的完整命令：

```bash
PYTHONPATH=harness python -m docforensics run samples \
  --state state/project-report-01 --fixture-repairs samples/fixture_repairs.json
```

报告会明确标注 fixture。第二次使用同一目录运行可核对跳过行为；输入、检查器、依赖、模型或 Skill 变化会使旧状态失效。独立评测应使用新目录。全部体验方式见 [README](../README.md)。

完整 Studio 需安装 `webui/requirements.txt`，准备 Tectonic、Poppler、中文字体和实际已下载的模型，再按 README 设置认证和编译器配置。模型推理在节点内运行；仅运行一个 Uvicorn worker。Tectonic 初次可能下载包，因此没有宣称整体流程离线。[Tectonic 项目说明](https://tectonic-typesetting.github.io/en-US/)

源码包只包含提交中的文件，不包含 Git 历史、用户上传目录、运行凭据或本地测试环境。新的 GitHub 仓库按团队要求保持私有。评委访问方式需在最终提交前落实；私有链接本身并不代表评委可打开。

## 限制与后续计划

已有明确许可的12条先导样本与人工复核导入流程；优先完成具名独立复核，再扩展跨来源的自然错误，分别测量问题召回、候选语义正确率、误改率和人工介入比例。之后再接入真实图像证据和 OCR 输出，验证原始区域与修复内容的对应关系。

产品层面需要增加多用户隔离、可靠作业队列和整项目上传。当前已保存任务接收、逐条事件及完成结果，服务重启可查询旧任务；中断后不自动重跑。进程内调度和第一页面预览仍不适合对陌生用户开放上传。当前表格检查有格式与数值表达限制，不应在复杂报表上自动采纳重算结果。

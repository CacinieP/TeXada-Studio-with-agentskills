# TeXada Studio v0.2.0-beta.4

预发布，macOS 15+ / Apple Silicon；应用短版本为 0.2.0，build 4。
本版集中交付 beta.3 之后的 OCR 审阅、来源保护和报告能力，并完成一份原创混合页面的本机真实链路验收。

## 新增与修复

- OCR 文本行经明确 accept/reject 决定转为 `layout.json`，审阅绑定原始记录哈希；未处理或无法解析的内容阻止布局生成。
- PNG 原图哈希与操作者像素框绑定；检查与续跑前验证图片字节、尺寸和区域，防止换图后复用旧证据。
- CLI 报告保留原图快照、带框/放大视图与 OCR 原文，完整运行目录可离线搬移和重建。
- 专用 OCR CLI 将后端截断、结束状态未知、拒绝、非文本标记和异常字符转入统一待审清单，保留诊断；不以 accept 或矛盾 OK 标签放行异常。
- 新增显式 `--profile minicpm-ocr`，采用官方识别提示词和解码参数。通用 profile 仍为默认；Studio 通用视觉导入单独配置、单独报告。

## 本机真实验收

- 原创一页样本含正文、两条公式、表格；表格故意印错合计 20（12+7=19），用于区分忠实转写与后续算术修复。
- 专用 MiniCPM-OCR F16 + DSpark，真实 OpenAI 兼容请求返回 13 行候选并保留 20。表格仅有空格分隔，原始布局转换被阻止；agent 明确补充分隔符后进入检查，得到 OK=9 / NEEDS_HUMAN=1，其中七个正文节点为未验证的 pass-through。换图被阻断，续跑复用十个节点。
- Studio 独立使用 MiniCPM-V4.7-1B Q4。两次真实导入均保留数字，但原始候选混入 `<table>` 和多余 `}`，编译报 Too many }'s。agent 移除这两行、未改数字后编译通过，再通过界面创建文档。
- 表格修复先拒绝并保留 20，再重新生成、明确采用 19、保存并刷新，最后从界面下载 PDF/TeX。两次修复任务的模型请求数均为 0。
- 本机 583 项 Python 测试及四组 JavaScript 回归通过。原始候选、失败、明确修订、模型身份和复现脚本见 [验收记录](../evaluation-results/beta4-acceptance-01/README.md)。

## 使用与边界

模型服务另行配置，安装包不包含模型权重；本轮验证的是本机 1B Q4 和专用 OCR，不代表默认 35B 或其他模型均已实测。

本轮是一份原创样本的真实 smoke，审阅由 agent 执行，不是独立人工质量复核，也不是 OCR 准确率或模型默认资格评测。自动区域获取和实际图像对应的进一步验收仍由 issue #24 跟踪。原图区域来源于已知 PDF 参考几何，不是模型自动检测。

报告搬移需保留整个运行目录（尤其 `sources/`）；SVG 直接链接到同目录 PNG，原图也作为独立回退。只对 PNG 来源执行绑定，不自动补齐缺失转写，也不生成概率置信度。

正式标签、源代码 ZIP/manifest/SHA256、签名公证 DMG 和安装包验收结果，在对应 Release 与发布 PR 中记录最终提交和下载摘要。安装包应以附带的 `checksum.txt` 校验：

```bash
shasum -a 256 -c checksum.txt
```
